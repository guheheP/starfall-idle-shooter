# STARFALL ビジュアル設計

装備を選んだ結果が機体と射撃に見えること、弾幕を読んで操作できること、撃破の気持ちよさを同じ画面で成立させる。現在の実装は、暗い宇宙背景、金属の機体、白い芯のあるエネルギー弾を共通の表現としている。

## 戦闘を読むための余白

背景の主役は上部と周辺に置き、中央と下部は暗い紺で静かに保つ。巡航・イオンは青い惑星と星雲、残骸回廊は銅色の巨大な残骸、極光前線は紫と青の氷惑星、虚空宙域は翡翠色の降着リングで場所を区別する。新しい背景が読み込まれている宙域では、コードによる構造物を重ねず、淡い環境光だけを添える。

演出を増やす時の優先順位は、自機の中心と敵弾、敵の射撃予告、武器と命中、報酬、背景装飾の順とする。敵弾には暗い輪郭と明るい芯を付ける。自機の中心点、敵HP、精鋭の予告は装飾とは別に描き、光の量だけで重要度を示さない。

## 武器の形を覚えられるようにする

| 系統 | 現在の見た目と動き |
| --- | --- |
| パルス | シアンの細い二連射。短い白い芯で高速射撃を見せる |
| スプレッド | 橙色の五方向散弾。扇形の広がりで面を覆う |
| ランス | 紫色の長い光線。太い芯と残光で貫通の力を見せる |
| ミサイル | 金属の弾頭・尾翼と橙色の噴射。曲がる光跡から誘導を読める |
| アーク | 青い折れ線と電撃連鎖。光の接続で次の対象を見せる |
| オービット | 金色の回転する結晶。八枚の花弁から前方へ広がり、緩やかに追尾する |

会心は金色の星状の閃光、凍結は氷色の印と敵の氷片、吸収は緑の光として重ねる。吸収の回復軌跡は、実際にシールドを回復した時だけ発生する。ランダム効果を重ねても、元の武器の形が分かるようにする。

凍結追撃の命中演出は、すでに減速中の敵に追加ダメージが乗った時だけ氷片を散らす。電撃連鎖は実際に到達した点に小さな菱形を置き、接続の範囲を読めるようにする。高シールド時の火力強化は機体の金色の輪で示し、強化された射撃には控えめな金色の光を添える。この弾の印は射撃時の条件を保持し、装備交換後も飛翔中の弾の状態を正しく表す。

## 敵の攻撃を予測できるようにする

精鋭は通常機とは違う金属の輪郭・発光部・短い名称を持つ。ヴァンガードは三方向、スナイパーは長い照準線、バラージは六方向の予告で攻撃を区別する。スナイパーは予告中に狙いを固定するため、見てから移動する判断につながる。ボスも扇状・旋回・交差の射撃方向を予告し、第2形態は発光や表示でも変化を伝える。

ボスの識別は輪郭から始める。WARDENは横へ広がる砲艦、HELIXは環状のコイルと3枚の刃、BASTIONは4枚の厚い装甲と十字の動力部を持つ。各機の第2形態では装甲が開き、コアが強く光る。3種類×2形態のテクスチャと、造形に合った発光コアの位置を別に定義する。本体を回転させず、コアの重ね描画を合わせる。攻撃パターンは既存の扇状・旋回・交差に対応させる。

命中、通常撃破、精鋭撃破、ボス撃破で光の大きさと余韻を変える。ボスは大きな水平衝撃波と長めの余韻を持つ。CR表示は同じフレームの撃破をまとめ、数字で戦闘を覆わない。自動売却と低レアの回収は控えめにし、保管したレア以上の装備を光柱とレア度色で強調する。

## ビルドを機体に表す

機体本体はモジュールと武器の組み合わせで変わり、ウイング・ボディ・ドローンは選んだモデルの部品を重ねる。リアクターは高シールド時にコアが発光し、バスティオンは装甲と六角形の輪郭、サイフォンは吸収系の色を持つ。支援機の数・姿・弾形も装備に合わせる。強化段階は機体の発光の細部に反映する。

自機24種と部品9種は、白いセラミック、青鋼のチタン、黒鉛の主機を明確な面で分ける。光を面全体へ焼き込まず、ベベル・継ぎ目・吸入口・レンズで材質を見せる。砲身、散弾砲、レール、ミサイルポッド、コイル、環状発射器は輪郭から区別し、ボディの上部中央は開けて操縦席を残す。

通常敵は銅色の細い三叉機、赤い広翼機、青鋼の重装機に分ける。精鋭は突撃装甲、長い中央レール砲、三連弾幕ポッドを載せ、色以外の違いを作る。発射口の充電光は実際の射撃待ち時間・精鋭の充電に合わせる。機体の寸法・中心・戦闘判定は変えない。

装備カードと倉庫の詳細には、武器6系統・部品9種の機械図を表示する。レア度は図の形を変えず、縁とラベルで示す。広い画面は整備グリッド上の図、低い画面とモバイルは品名横の小さい図に切り替える。

装備の比較、強化、自動売却、研究、図鑑はドックとダイアログに収める。ゲーム本体は画面全体を使い、倉庫を開くと戦闘を止める。比較情報は内部だけをスクロールし、強化・装備・保護・売却の操作を見失わない構成にする。

「組み合わせ」は構成と相性の2タブに分ける。構成は名前付きで3組を保管し、4部位とモジュールをまとめて呼び出す。CRは消費せず、HPの割合・次の射撃までの待ち時間・発動中の必殺技・吸収予算をリセットしない。保存は装備IDだけを参照する。参照中の品を一括整理・容量整理から保護し、個別売却では影響する構成を確認する。欠品構成は消さずに呼び出しを止め、再出撃後も保管する。

相性の表示は「成立している組み合わせ」と「今の発動条件」を区別する。凍結追撃は減速中の敵数、高シールド維持は70%の条件と現在のシールド率を添える。高シールド維持の回復手段には自然再生も含む。会心・範囲の補正は成立時に適用される。表示と演出は既存の補正を可視化し、装備選びと戦闘の結果を結び付ける。

## 派手さの上限と演出OFF

発光は局所的で短くし、全画面を白く覆う演出を常用しない。現在の上限は、砲口・命中などの光56個、弾の追加光跡96本・各6点、火花400個、破片70個、輪60個、電撃の接続20本、吸収の軌跡30個。文字・残像・回収クリスタルなどの一時オブジェクトも上限で抑え、寿命が終われば破棄する。

撃破は白熱する芯、橙色のプラズマ、暗い外周の雲、金属片の明るい縁を組み合わせる。雲は同じ形が膨らむ12枚のフレームを一度だけ生成し、最大24枚の再利用スプライトで描く。通常・精鋭・ボスと武器の爆風で大きさと余韻を変える。敵弾と自機の中心は、爆発・報酬文字・回収結晶より上の層へ置く。通常撃破ではカメラを揺らさず、精鋭・ボス・被弾・必殺技の変化を強調する。

エフェクトOFFとOSの動きを減らす設定では、揺れ・閃光・粒子・追加光跡・残像を止め、星と環境光の動きも止める。機体、弾の基本形、中心点、HP、敵の射撃予告は残す。演出の量を変えても戦闘の規則は変えない。

## 実装と素材

`scene.ts`が表示を統合し、自機・部品は`ship-visuals.ts`、通常敵・精鋭・機械の光は`enemy-visuals.ts`、弾は`projectile-visuals.ts`、撃破の雲は`destruction-visuals.ts`が担当する。`combat-visuals.ts`は局所的な光と追加光跡、`environment-visuals.ts`は環境の補助描画を担当する。旗艦の造形とコア位置は`boss-visuals.ts`、背景の対応と読み込みは`visual-assets.ts`に置く。装備の機械図は`ui/gear-art.ts`で生成する。いずれも戦闘判定は変更せず、`simulation.ts`の結果を描画する。保存構成の参照と検証は`loadouts.ts`にまとめる。

背景PNGと完全な生成プロンプトのJSONは`public/assets`に並べて保管する。生成画像には機体、弾、UI、文字を含めず、動く要素はゲーム側で描く。素材を差し替える時も中央の暗さ、ランドマークの位置、武器と敵弾の読みやすさを保つ。
